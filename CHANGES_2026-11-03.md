# MMS Recruitment Portal — update of 03-11-2026

## 1. Data Import & Migration (HR Admin → `/import`)
- Page renamed from "Excel Import"; now opens with a **Download templates** panel for all 5 templates (Requisitions, Candidate Master, Candidate-Requisition Mapping, Interview Details, Recruitment Partners & Costs).
- Templates (`backend/templates_xlsx.py`): Instructions sheet, dropdowns from master data, mandatory headers (black, `*`), either/or headers (amber, `†` — Email / Mobile), DD-MM-YYYY date, numeric, email and 10-digit mobile validation, yellow `[SAMPLE]` rows that are never imported. Fixed the costs sample row's category name.
- Workflow: upload → preview (first rows, template auto-detected and auto-mapped) → validate (row/column-level errors, duplicates, sample rows) → download error report → confirm. If any row has errors, HR must tick "import valid rows only" or fix the file first.
- Options: **Update existing records (overwrite)** — off by default; **Add unknown values to master data** — off by default (unknown department / recruiter / role / partner is an error).
- Summary: Total Rows, Successfully Imported (new / updated), Skipped, Duplicate Records, Failed Records.
- Integrity: candidates de-duplicated on email (case-insensitive) or mobile; requisitions on Requisition ID; mapping on candidate+requisition; interviews on application+round; costs on partner+invoice. IDs auto-generated when blank. Import is all-or-nothing: on failure every insert/update is rolled back, filled positions are recounted and no activity-log entries are left behind.

## 2. Test / demo data cleanup
- Super Admin → Master Data & Settings → **Data cleanup** tab: shows target environment, database name and host, per-table counts, what is preserved; requires the phrase `DELETE ALL RECRUITMENT DATA` **and** the database name. Returns per-table deleted counts and verifies all tables are empty.
- CLI for the server: `python scripts/cleanup_recruitment_data.py` (dry run) → `--yes --database <DB_NAME>`; asks again if `APP_ENV=production`.
- Deletes requisitions, candidates, applications, interviews, feedback, selections, offers, joinings, costs, notifications, activity, file records, import batches, ID counters, and TEST_ / @mms.test users. Keeps users, Super Admin, masters, settings, roles, indexes. Nothing is re-seeded.

## 3. Age per Hire = Actual Date of Joining − CRF Raised Date
- Dashboard: Age per Hire panel (avg, median, min/max, vs previous month and quarter, monthly/quarterly trend, current hiring age of open requisitions, data-completion count) with department / role / recruiter / source / date filters.
- Analytics → **Age per Hire** tab: breakdowns by department, role, recruiter, partner, source; hire list with flags; open requisitions missing CRF. Reports → Age per Hire export.
- Requisitions list/detail flag a missing CRF Raised Date. No date is substituted; negative durations are flagged and excluded; non-joined candidates are excluded.
